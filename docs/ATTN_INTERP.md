# Attention Interpretability Report

**Models**: `hmn_chunk_global_iq_rw_nc4_slot8_wina_s0` (IQ-only, step 80k, MEAN 30.6%)  
**and**: `hmn_chunk_global_iq_rw_nc4_slot8_ir_v2` (IQ+IR2, step 60k, MEAN 77.8%)  
**Architecture**: nc=4, chunk_len=16, slot_len=8, warmup_len=8, n_refine=2 (IR only)  
**Method**: `F.scaled_dot_product_attention` replaced in-context; head-averaged weights across 8 val sequences × 4 layers

---

## Sequence layout (slot_len=8, nc=4)

```
[enc_block 0: src 0:16 | slot 16:24 ]
[enc_block 1: src 24:40 | slot 40:48 ]
[enc_block 2: src 48:64 | slot 64:72 ]
[enc_block 3: src 72:88 | slot 88:96 ]
enc_end = 96

[IQ:   slot 96:104 | warmup 104:112 | output 112:136 ]
[IR1:  slA 136:144 | argmax 144:168 | slB 168:176 | warmup 176:184 | output 184:208 ]
[IR2:  slA 208:216 | argmax 216:240 | slB 240:248 | warmup 248:256 | output 256:280 ]
```

Column region labels used below:
- **enc_src**: raw source byte positions (0:16, 24:40, 48:64, 72:88)
- **enc_slot**: enc_block SLOT positions (16:24, 40:48, 64:72, 88:96)
- **IQ_slot / IR_slA / IR_slB**: recall SLOT positions
- **IQ_warm / IR_warm**: warmup positions
- **IQ_out / IR_out**: output positions
- **null/other**: null_kv token + any prior-turn non-output tokens not listed above

## IQ-only model (slot8_wina_s0, step 80k)

### IQ_SLOT rows (pos 96:104) — the encoding query

| warmup_x | enc_src | enc_slot | IQ_slot (self) |
|----------|---------|----------|----------------|
| x=0  | 0% | **80%** | 20% |
| x=16 | 0% | **80%** | 20% |
| x=32 | 0% | **80%** | 20% |

**Interpretation**: IQ SLOT tokens read 80% of their attention from the enc_block SLOTs
(the 4×8=32 compressed-memory positions). The remaining 20% is within-SLOT causal
self-attention (the 8 SLOT tokens reading earlier SLOT tokens in the same block).
`enc_src=0%` confirms the mask is intact — SLOT never reads raw source bytes.

Invariant across all three warmup offsets: SLOT encoding does not depend on which
window the warmup seeds. The same 80/20 split holds for x=0 (Win A), x=16 (Win B),
x=32 (Win C). This is correct — the SLOT encodes the full source, not a specific window.

### IQ_warmup rows (pos 104:112)

| warmup_x | enc_src | enc_slot | IQ_slot | IQ_warm (self) |
|----------|---------|----------|---------|----------------|
| x=0  | 0% | 0% | 52% | 48% |
| x=16 | 0% | 0% | 60% | 40% |
| x=32 | 0% | 0% | 60% | 40% |

**Interpretation**: Warmup tokens read exclusively from IQ_SLOT (52–60%) and from
prior warmup tokens (40–48%). The mask correctly blocks enc_src and enc_slot here.
The warmup is using the SLOT as a lookup key: "given these 8 compressed bytes, what
byte value should come next at position X?"

The slight increase in IQ_slot attention for x=16/32 vs x=0 suggests warmup tokens
for later windows lean more on the SLOT (less warmup context before them in the
sequence, since warmup_x is a byte offset not a token offset — the actual warmup
token positions are fixed at 104:112 regardless of x).

### IQ_output rows (pos 112:136)

| warmup_x | enc_src | enc_slot | IQ_slot | IQ_warm | IQ_out (causal) |
|----------|---------|----------|---------|---------|-----------------|
| x=0  | 0% | 0% | **55%** | 5% | 40% |
| x=16 | 0% | 0% | **57%** | 4% | 40% |
| x=32 | 0% | 0% | **52%** | 4% | 44% |

**Interpretation**: This is the critical path. Each output byte is generated by attending:
- **~55% to IQ_SLOT** — the compressed memory. This is the primary recall signal.
- **~40–44% to prior output tokens** — standard AR causal self-attention. Each byte
  conditions on bytes already generated.
- **~4–5% to warmup** — the seed bytes, used mainly for the first output token.

The information flow is clean: `enc → enc_slot → IQ_slot → output`. No raw source
bytes reach the output at any point. The ~40% causal output attention is expected and
healthy — an AR model generating bytes sequentially will naturally use prior output
as context. The SLOT is the primary source (~55%), not the autoregression.

**Why Win A fails**: all attention patterns are correct. The SLOT reads from enc_slot
(80%), the output reads from SLOT (55%). The failure is information capacity, not
routing. 8 SLOT tokens must compress 4×16=64 bytes; for Win A the first-window
recall requires recovering byte 8..31 from scratch (warmup at 0:8 is known). The
SLOT simply does not have bandwidth to store enough of the 64-byte source for the
hardest window at IQ-only.

## IQ+IR2 model (slot8_ir_v2, step 60k, 77.8%)

### IQ turn — same structure as IQ-only

| rows | enc_src | enc_slot | IQ_slot | IQ_warm | IQ_out |
|------|---------|----------|---------|---------|--------|
| IQ_SLOT  96:104 | 0% | **84%** | 16% | — | — |
| IQ_warmup 104:112 | 0% | 0% | 38–45% | 55–62% | — |
| IQ_output 112:136 | 0% | 0% | 35–46% | 5% | 49–59% |

IQ SLOT enc_slot share slightly higher (84% vs 80%) compared to IQ-only — the
presence of IR training appears to sharpen the IQ encoding step. IQ output SLOT
share is lower (35–46% vs 52–57%) and causal output share is higher (49–59% vs
40–44%). This is consistent with IQ being an "initial guess" in the IR model —
IQ is less precise, IR corrects it.

The warmup_x=32 case shows the largest causal shift (IQ_out=59%) — Win C IQ output
relies more on autoregression, which is consistent with Win C being the hardest window
for IQ (it's last, the warmup x=32 starts near the end of the 64B source).

### IR1 turn

#### IR_SLOT_A (pos 136:144)

| warmup_x | enc_src | enc_slot | IR_slA (self) | null/other |
|----------|---------|----------|---------------|------------|
| x=0  | 0% | **72%** | 15% | 13% |
| x=16 | 0% | **71%** | 16% | 13% |
| x=32 | 0% | **71%** | 16% | 13% |

SLOT_A reads 71–72% from enc_slot — same bottleneck as IQ SLOT, just using a separate
set of 8 token positions. The 13% null/other is the null_kv token (model has a learned
"attend to nothing" option which is used ~13% of the time here). SLOT_A is essentially
a second encoding query, independent of IQ.

#### IR_argmax (pos 144:168) — the error signal

| warmup_x | enc_src | enc_slot | IR_slA | IR_am (causal) | null/other |
|----------|---------|----------|--------|----------------|------------|
| x=0  | 0% | **51%** | 10% | 15% | 24% |
| x=16 | 0% | **51%** | 10% | 15% | 24% |
| x=32 | 0% | **51%** | 11% | 15% | 24% |

Argmax rows attend 51% to enc_slot and only 15% to prior argmax tokens (the IQ
predictions themselves). The 24% null/other includes: the null_kv token, and prior
IQ rec_block tokens (IQ_slot, IQ_warmup — which are not classified as outputs and
therefore reachable).

**Key insight**: argmax rows read mostly from enc_slot (51%), not from the argmax
values (15%). This is surprising — one might expect argmax to primarily process "what
IQ predicted" and compute an error signal. Instead, the model uses argmax positions
mostly as additional enc_slot queries. The argmax tokens carry position information
(their token values are IQ's byte predictions) but the model reads enc_slot through
them rather than attending to the predictions themselves. The actual correction
information flows through SLOT_B.

#### IR_SLOT_B (pos 168:176) — the correction gate

| warmup_x | enc_src | enc_slot | IR_slA | IR_am | IR_slB (self) | null/other |
|----------|---------|----------|--------|-------|---------------|------------|
| x=0  | 0% | **71%** | 7% | **8%** | 6% | 8% |
| x=16 | 0% | **70%** | 6% | **8%** | 6% | 8% |
| x=32 | 0% | **71%** | 6% | **8%** | 7% | 8% |

SLOT_B reads 70–71% from enc_slot, 8% from IR_argmax, 6–7% from SLOT_A.

**Critical finding**: SLOT_B re-encodes from enc_slot (70%) rather than operating as
a delta on SLOT_A or the argmax. It builds a near-independent compression of the source,
with only 8% attention to argmax as a hint. The model's use of IR is not
"take IQ output, compute correction, add delta" — it is "re-read enc_slot from a fresh
perspective informed by the argmax hint."

This explains why IR works so well: each IR turn is an additional, near-independent
compression attempt that uses the prior prediction (argmax) only as a weak prior. SLOT_B
can contradict SLOT_A entirely; the output just reads SLOT_B.

#### IR_warmup and IR_output

| rows | IR_slA | IR_am | IR_slB | IR_warm | IR_out (causal) |
|------|--------|-------|--------|---------|-----------------|
| IR_warmup 176:184 | 0% | 0% | **42–49%** | 51–58% | 0% |
| IR_output 184:208 | 0% | 0% | **40–45%** | 5% | 49–55% |

Warmup and output read exclusively from SLOT_B and their own causal context. enc_src,
enc_slot, SLOT_A, and argmax are all absent. The bottleneck is clean: output only
sees SLOT_B (the correction) and prior output (AR context).

### IR2 turn

| rows | enc_slot | IR_slA (self) | null/other |
|------|----------|---------------|------------|
| IR_SLOT_A 208:216 | **61%** | 8% | **31%** |

| rows | enc_slot | IR_slA | IR_am (causal) | null/other |
|------|----------|--------|----------------|------------|
| IR_argmax 216:240 | 42% | 10% | 6% | **42%** |

| rows | enc_slot | IR_slA | IR_am | IR_slB (self) | null/other |
|------|----------|--------|-------|---------------|------------|
| IR_SLOT_B 240:248 | **67%** | 5% | 4% | 4% | **20%** |

IR2 shows the same qualitative pattern as IR1, with higher null/other shares (31%,
42%, 20%). The increase in null/other across turns reflects IR2 having more prior
context available — IR2's SLOT_A/argmax/SLOT_B can attend to IR1's SLOT_A, argmax,
SLOT_B, warmup (not blocked). This gives the model access to IR1's intermediate
representations. The null token absorbs attention that would otherwise go to irrelevant
positions — effectively a soft no-op gate.

IR2 warmup/output are identical to IR1 (IR_slB=42–48%, IR_out=49–55%), confirming
that each IR turn uses the same recall mechanism independently.

### Cross-turn consistency

IR1 and IR2 show essentially identical structural patterns — enc_slot is the dominant
source for all SLOT rows in both turns (~61–72%), IR_slB drives warmup/output in both
turns (~42–49%). The mechanism does not change between turns; the model runs the same
"re-encode from enc_slot, write to SLOT_B, output reads SLOT_B" circuit twice.

## Summary

### Information flow diagram

```
Source bytes
    │
    ▼ (enc_block forward, Rule 2: enc_slot[k] blocked from enc_src[j≠k])
enc_slot[0..3]   ─────────────────────────┐
    │                                     │
    ▼ (80–84% of IQ_SLOT attention)       │
IQ_SLOT (8 tok)                           │
    │                                     │
    ├──46–57%──▶ IQ_output (AR chain)     │
    │                                     │
    └──IQ argmax (greedy decode)          │
                                          │
    ┌─────────────────────────────────────┘
    ▼ (71–72% of IR_SLOT_A attention)
IR_SLOT_A (8 tok) ──8%──▶ argmax hint
    │
    ▼ (70–71% of IR_SLOT_B from enc_slot, 8% from argmax)
IR_SLOT_B (8 tok)
    │
    └──40–45%──▶ IR_output (AR chain)
```

### Mask violations: none

`enc_src=0%` in every row type across all turns and all warmup offsets. The
architecture enforces the bottleneck correctly. The model never shortcuts through
raw source bytes.

### Key findings

1. **Bottleneck holds**: enc_src reads are 0% everywhere. All recall flows through
   SLOT tokens.

2. **SLOT reads are concentrated**: IQ_SLOT reads enc_slot at 80–84%. This is
   high specificity — the SLOT is doing meaningful compression, not diffuse attention.

3. **Output reads SLOT as primary source**: IQ/IR output rows read their SLOT at
   40–57%, with 40–59% causal AR self-attention. Both channels are active; SLOT is
   the leading source for earlier windows (Win A/B) while causal dominates for Win C
   (x=32), which the model generates more autoregressively.

4. **IR is not a delta encoder**: SLOT_B reads enc_slot at 70–71%, argmax at only 8%.
   Each IR turn independently re-encodes from enc_slot, using argmax as a soft hint.
   This is more like "re-read with context" than "compute error and add correction."

5. **IR2 reuses IR1's intermediate representations**: The 31–42% null/other in IR2's
   SLOT_A/argmax rows includes IR1's SLOT_A/argmax (not blocked by mask). The model
   builds on prior-turn query representations, not just the output.

6. **Null_kv absorbs "nowhere useful" attention**: ~8–13% null attention in IR SLOT rows
   (vs ~0% in IQ SLOT rows). IR turns have access to more candidate positions but often
   prefer the null token over attending to less-relevant prior-turn tokens.

7. **Win A failure is capacity, not routing**: IQ_SLOT correctly attends enc_slot (80%)
   for all three windows. The failure at Win A is that 8 SLOT tokens cannot store enough
   information to recover bytes 8:32 from a 64B source. The attention mechanism works
   correctly; the storage bandwidth is the bottleneck.
